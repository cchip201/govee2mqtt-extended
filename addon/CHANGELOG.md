* feat(undoc-api): support 2FA login codes for Govee accounts

Why: accounts with 2FA enabled return status 454 on /v1/login. Detection
shipped in #15 but the addon had no way to actually pass a verification
code through to Govee, so 2FA users were stuck. This adds the code
submission path and 455-handling for rejected codes.

- Add `govee_2fa_code` schema field (config.yaml) + GOVEE_2FA_CODE env
  export and redaction (run.sh).
- Add `--govee-2fa-code` CLI flag and `with_code()` builder on the API
  client; the code is appended to the login JSON body when set.
- Detect status 455 (invalid/expired code) alongside 454; both bail with
  a hardcoded user-facing message (no raw response body in errors).
- Add `cache::NoCacheError` marker so 454/455 bails skip the negative
  cache write entirely. Defensive belt-and-suspenders on top of #15's
  short negative_ttl — guarantees the user can retry within the code's
  ~15 min validity window even if the TTL is later raised.
- Document the flow in docs/CONFIG.md.

* fix(undoc-api): clear 2FA code after successful login

Wrap `GoveeUndocumentedApi::code` in `Mutex<Option<String>>` and null it out
inside `login_account_impl` immediately after a successful login response.
Without this, the one-shot code was held for the process lifetime and replayed
on every ~12 h token refresh, causing silent 455 failures and HA device
outages for accounts with 2FA enabled.

Manual `Clone` impl creates a fresh `Mutex` from the current value so the
existing `state.rs` clone path continues to work.

* fix(undoc-api): address pre-landing review findings

Three fixes from adversarial review:

- Store code-cleared client in state (serve.rs) so the persisted instance
  never replays a stale 2FA code on token refresh; previously the clear
  happened on a transient clone while the original retained the code
- Use unwrap_or_else on Mutex::lock to recover from poison rather than panic
- Clamp token_expire_cycle to 60 s minimum to prevent Govee-server-controlled
  login-request amplification on a zero TTL
